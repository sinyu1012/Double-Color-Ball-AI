# 当前策略审计与 v4 prompt 设计

审计日期：2026-09-22。审计基线提交：`d24b4ac`。下文的数据与组合概率来自该基线快照；用户确认后已接入 `prompt4.0.md`，并同步修复重试上下文，接入详情见后文。候选生成算法、历史数据与前端未改动。

## 结论

有明确优化空间的是固定预算下的多注覆盖、评价指标和实验留痕。目前没有可靠证据说明冷热、遗漏、周期或更强的语言模型能提高单注中奖概率。

在每期独立、所有合法号码等概率的模型下，每注一等奖概率都是 `1 / (C(33,6) × 16) = 1 / 17,721,088`。五注互不相同的完整号码对应 `5 / 17,721,088`；调整红蓝球的分散程度不再增加这个头奖概率。单注平均红球命中数为 `6 × 6/33 ≈ 1.0909`，蓝球命中概率为 `1/16`。这些是数学基准，不是历史回测结果。

本建议默认比较“每期 5 注、每注 2 元”的方案，不增加预算。任意奖、回本和头奖是不同目标。让更多期至少中一次小奖，并不等于更容易回本或提高期望收益。

## 审计基线中的真实策略

- 审计基线的 `generate_ai_prediction.py:29` 读取 `doc/prompt3.0.md`，并非 v2 的自由选号 prompt；本次接入后已改为 v4。
- `prediction_rules.py` 先计算统计，每策略生成 8 个合法候选；模型只能返回 5 个 candidate_id。

## 优化优先级

| 优先级 | 发现与建议 | 仅改 prompt 能否完成 |
|---|---|---|
| 1 | 若目标是至少中一次小奖，先减少五注蓝球重复；当前五策略固定蓝球为 `02、01、04、02、02` | 不能，必须修改蓝球候选生成 |
| 2 | 用中奖期率、中奖注率、奖级、奖金/成本分别评价；总命中球数仅作辅助指标 | 不能，需要调整评估逻辑 |
| 3 | 将五组联合选择，减少红球交集并扩大覆盖 | 可以，v4 已明确目标；是否达标仍需程序核验 |
| 4 | 候选生成增加覆盖差异；冷热与形态约束保留为可检验假设，另设无形态约束的随机对照 | 不能，需要修改候选算法 |
| 5 | 固定版本、开奖前存档并持续积累样本，与同预算基线比较 | 不能靠 prompt 单独保证 |

如果五注分别使用 5 个不同蓝球，“至少一注中蓝球”的概率从 `3/16 = 18.75%` 增加到 `5/16 = 31.25%`，增加 **12.5 个百分点**。这是蓝球覆盖事件，不是任意奖总概率；蓝球命中注数的期望仍为 `5/16`。集中同一个蓝球会让中蓝时多注同时中奖，分散则增加至少中一次的机会，属于中奖分布的取舍。

当前每策略内部 8 个候选共有的红球数量分别为 `3、3、3、3、2`，可见枚举结果较集中。平衡策略的所有形态硬约束允许 `59,206 / 1,107,568 ≈ 5.35%` 的红球组合；和值 `100–120` 覆盖约 `34.64%`。这不使所选单注更好或更差，但也不能据“形态常见”推导某一具体号码更容易开出。

## 仅换 prompt 的空间有多大

以最新真实历史生成的候选为固定输入。离线穷举 `8^5 = 32,768` 个五注方案，并计算至少一注命中 4 个或更多红球的开奖结果并集。这里的候选顺序对照只是一个确定性基线，不代表 v3 模型的实际输出。

在不启用福运奖、仅计算基础六奖时，设不同蓝球数为 `k`，能使至少一注命中至少 4 红的红球开奖结果数量为 `U4`：

`P(至少一注获基础奖) = k/16 + (16-k)/16 × U4/C(33,6)`

原因是蓝球命中任意一注即可获基础奖；蓝球不在所有已选蓝球中时，至少一注中 4 红才获基础奖。计算假设红蓝开奖独立、合法组合等概率。

| 方案 | 不同蓝球 | 红球并集 | 最大两注红球重合 | U4 | 至少一注获基础奖 |
|---|---:|---:|---:|---:|---:|
| 每组选第一个候选 | 3 | 21 | 4 | 26,033 | 20.659753% |
| 分散指标最优之一，也达到当前 U4 最大值 | 3 | 23 | 2 | 27,104 | 20.738320% |
| 当前候选空间 U4 最小值对应方案 | 3 | — | — | 24,350 | 20.536290% |

第二行的 candidate_id 为 `1-04、2-01、3-03、4-05、5-06`。这仅是快照审计样本，不应硬编码为之后每期的选择。

对这个快照，分散方案比“全选第一个”只增加 **0.078567 个百分点**；整个候选空间最差到最好也仅差 **0.202030 个百分点**。这些是精确组合概率，不是 LLM 实测改进，也不是 v4 的历史胜率。没有运行 v3/v4 模型对照实验，不能宣称模型必然选择到该方案。

若当期启用福运奖，至少获一个奖的红球门槛变为 3，此时应用同一公式并把 `U4` 改为 `U3`。上述前两方案的 `U3` 分别为 `272,287` 和 `298,910`，对应 `38.724682%` 和 `40.677717%`；这两个值仅适用于启用福运奖的条件场景，且未宣称第二个方案是该场景全局最优。

## 规则版本必须进入评估

官方规则自 `2026014` 期（2026-02-01）变更，特别规定期间设有 3+0 中 5 元的福运奖。奖池达到 15 亿元启动，启动后低于 3 亿元才停止；不能把所有 2026 年期次都标成启用，也不能仅根据当期奖池低于 15 亿元判定停止。见[官方规则变更公告](https://www.swlc.net.cn/article/403a79b8-ae7b-4e38-9b17-c98f454c03d1.html)与[深圳福彩对福运奖的说明](https://www.szlottery.org/fcw/fcxw/csdt/content/post_1659014.html)。

项目开奖记录只有日期、期号和号码，缺少逐期奖金及特别规定状态。应使用“启用 / 停用 / 未知”三态，未知时只报告基础奖口径，不虚构实际总奖金。本次没有核实 `26110` 的特别规定状态。

## 新版 prompt 的作用与接入边界

`doc/prompt4.0.md` 沿用 `{target_period}`、`{target_date}`、`{candidate_plan}` 和现有 selections JSON 协议，新增如下明确目标：

1. 不把历史得分当中奖概率。
2. 优先扩大不同蓝球覆盖；当前候选蓝球固定时自动跳过该比较。
3. 联合最小化最大红球交集和交集平方和，再扩大红球并集。
4. 固定平手规则，不把分散目标变成可能无解的新硬约束。
5. 保留合法候选选择，禁止改号码、编造统计或声称全局最优。

这些是可解释的分散指标，不等同于任意奖概率的精确优化。在当前快照两者恰好有相同最优方案，也不能外推到每一期。

用户确认后，`PROMPT_FILE` 已切换至 v4，`GENERATOR_VERSION` 更新为 `4.0`。输入指纹包含模板和生成器版本，因此不会把相同历史输入下的旧版本输出当作 v4 结果复用。模板渲染、响应协议和含模拟 API 的离线生成链路已验证；没有调用收费模型 API、生成正式新一期预测或证明模型遵循分散目标。

`_repair_prompt` 现在保留原始已渲染 prompt，并明确修复请求只返回 `pending_group_ids`；锁定组携带 candidate_id、红球与蓝球，参与完整五组的覆盖比较，但不能被重新选择。部分组修复、JSON 错误和连续修复均沿用同一套目标，不累积嵌套的修复 prompt。程序仍仅强制候选合法性和跨组红球不完全相同，没有强制分散指标达到全局最优；需要精确最优时应再实现程序优化器。

## 推荐的下一阶段实验

- 先固定目标为“相同 5 注预算的至少一次中奖概率”，单独报告回本率和头奖概率，避免混成一个胜率。
- 以程序精确计算组合覆盖作为优化器；候选空间仅 32,768 种，适合确定性枚举。LLM 可负责解释或作为实验选择器，不必承担可精确求解的优化任务。
- 建立同预算对照：5 注互异的均匀随机、5 个不同蓝球的随机方案、当前候选的确定性覆盖优化、同一候选下的 v3/v4 模型选择。前两项检验候选规则，后两项隔离 prompt/LLM 的额外作用。
- 算法回测只能用第 t 期之前的真实开奖生成第 t 期候选；参数先冻结，连续保留独立测试段，不在该段反复调参。过去日期的 LLM 可能记得开奖结果，LLM 优劣应优先用未来开奖前冻结的输出检验。
- 每期保存输入截止期、输入哈希、模板与规则版本、随机种子、模型请求/响应版本、生成时间、每组 candidate_id、不同蓝球数及覆盖指标；失败和缺失期也记录，不只保留成功样本。
- 分开计算中奖注率、中奖期率、各奖级次数、已知奖金/成本、回本期率。统计不确定性按“期”计算，同期开奖的多个模型和多注号码不能当作独立样本；多策略比较需要控制事后挑选偏差。
- 若没有超过相同覆盖设计的随机基线，就采用更简单的方案，不继续堆叠冷热、尾数、质数、周期或所谓高置信度评分。
